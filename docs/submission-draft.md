# Devpost submission draft — private real-data evaluation, synthetic public demo

## Project title

Stream Risk Envelope

## One-line description

A stream-record review aid that explains exceptions, exposes uncertainty and exports reasoned human follow-ups.

## Track and problem

**Track 3: AI-Supported Assessment.** Stream-monitoring coordinators and research QA reviewers have limited time to investigate inconsistent records. Stream Risk Envelope prioritises records for a person to inspect, shows why each was flagged, and lets that person record a disposition. It supports assessment without making a contamination, safety or health diagnosis.

## Why we built this check

We developed the method using OneAquaHealth Resilience Map data in a private repository. An initial landscape-context model failed to beat a mean baseline when cities were held out. We retained that negative result and narrowed the task to checking whether the faecal and pathogen indicators in the same record follow their observed cohort co-variation. We do not infer the antibiotic-resistance indicator from these two. The possibility of shared upstream measurement inputs remains unresolved, so this is a consistency check rather than an independent validation of either indicator.

## What the prototype does

A standardised ridge model predicts one indicator from the other. Split conformal calibration forms an interval using a separate calibration split. A reading outside its interval enters a ranked human review queue. The reviewer sees the observed value, expected envelope and distance outside it, then can accept plausible variation, suggest a field or lab re-check, or escalate context. A control shows how nominal level changes interval width and review workload. Records with an interval too wide to judge appear in a separate further-assessment queue; they are not automatically cleared. The reviewer must provide a reason and explicitly save. Each saved decision captures its operating point and synthetic evidence, and can be exported in a CSV handoff. Decisions persist locally unless exported; no request is sent to a field or laboratory team.

## Evidence from the private retrospective analysis

The method was evaluated on **96 actual OneAquaHealth Resilience Map records across five cities**, holding out each city in turn. At the default **80% nominal** operating point, the private evaluation recorded **82% empirical coverage** and **17 of 96 records** queued for review. The fitted model beat a mean-prediction baseline in each of the five held-out cities. These are **aggregate retrospective results from the private analysis**, not numbers generated by the public demo. They assess consistency-screening behaviour and workload; the data do not establish that flagged records were erroneous, that reviewer time was saved, or that ecosystem or human-health outcomes improved. The private data-derived snapshot and its Git history are not public, so the actual-data evaluation cannot be reproduced from this public repository alone.

## Public demo and data boundary

**Every site code, city, observation, plot, flag and performance number shown in the public interface is independently generated synthetic data.** The video shows only this synthetic interface and discusses the separate private evaluation using aggregate results. None of the plotted values is an actual OneAquaHealth measurement or a transformed copy of one. A OneAquaHealth representative confirmed in writing that actual Resilience Map data should not be extracted and republished as a dataset in a separate application or public repository, and directed the public hackathon repository to contain code, methodology, derived logic and a clearly labelled synthetic demo payload. We followed that direction with a new public repository and Git history. No actual site-level data or derived snapshot is redistributed. The public fixture demonstrates the interaction and code path; its metrics are not evidence of real-data performance.

## How we built it

Python, scikit-learn, pandas and NumPy implement the data access pattern, model, leave-one-city-out evaluation and split conformal logic. HTML, CSS, SVG and JavaScript provide the offline interactive demonstration. The public repository includes the model code, deterministic synthetic fixture, tests, method notes and an accessible site table. Its acceptance checks regenerate the fixture and rehearse the browser path without network calls. These checks verify the public synthetic demonstration, not the private real-data benchmark.

## Limits and next step

The real analysis is a single-season retrospective cross-section, not a forecast or field trial. A flag is a prompt to review co-variation, not a finding of measurement error, contamination or human-health risk. Standard conformal coverage requires exchangeability between calibration and test records. Cross-city distribution shift can violate that assumption, and marginal coverage would not ensure equal coverage within each city even when the assumptions hold. Observed interval coverage is not error-detection accuracy. The public prototype exports editable follow-up records but has no authenticated reviewer identity or audit history. A pilot would require permissioned data access, repeated local observations, city-specific calibration where possible, a responsible review team, and measurement of review time and re-check yield against a manual baseline.

## Preliminary usability feedback

One feedback report relayed by the project author highlighted that an empty exception queue could overshadow unassessable records, coverage percentages could be mistaken for accuracy, and request wording could imply delivery. We responded by showing all three outcome counts together at the top and beside the queue, explaining target coverage next to the control, moving observed coverage into method details, and labelling follow-ups as local recommendations. The handoff explicitly does not manage recipients, deadlines, delivery or re-test results. These changes have not yet been retested with that participant; no task-success rate, time saving or field effectiveness is claimed.
